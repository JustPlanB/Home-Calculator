# کارگاه — مدیریت کارهای پروژه‌ی ساختمانی

اپ موبایلی (وب‌ویو، قابل‌بسته‌بندی با Capacitor مثل حساب‌کتاب) برای برنامه‌ی روزانه، نقشه‌ی زمانی، گزارش ناظر و سفارش خرید.
ایده از یادداشت دست‌نویس صاحب پروژه آمده است. ظاهر و قواعد از اپ حساب‌کتاب گرفته شده‌اند.

**وضعیت:** شاکله و زیرساخت آماده است. بخش‌های انبار، مالی و مدارک هنوز «به‌زودی» هستند.

## اجرا

```bash
cd kargah
python3 -m http.server 8765      # بعد بازکردن http://localhost:8765
```

- راهنمای زنده‌ی همه‌ی اجزا: `styleguide.html`
- داده‌ها در `localStorage` ذخیره می‌شوند. اولین بار داده‌ی نمونه ساخته می‌شود؛ از منو می‌شود بازنشانی کرد.
- پشتیبان‌گیری و بازیابی (فایل JSON) از منوی بالا.

## آنچه ساخته شده

| صفحه | کار |
|---|---|
| اصلی | خلاصه‌ی امروز، پیشرفت کل، کاشی‌های ابزار، افزودن سریع، جستجو |
| کارهای امروز / فردا | کارها به تفکیک عملیات، تیک، انتقال خودکار ناتمام‌ها، بنر «همه انجام شد» |
| نقشه‌ی زمانی | نوار هر عملیات روی محور روز، خط امروز، جدول نفرات و پیشرفت |
| گزارش ناظر | پیشرفت نسبت به قبل، برچسب‌ها، ثبت سفارش از دل گزارش |
| سفارش خرید | جدول با ویرایش درون‌خطی و وضعیت |
| پرسنل | جدول با انتخاب عملیات |

## زیرساخت (برای ساخت بخش‌های بعدی)

قواعد و واژه‌نامه (جدول، کارت، دکمه… یعنی چه) در **`CLAUDE.md`** است. خلاصه:
رنگ فقط از `css/tokens.css`، آیکن فقط از `js/ui/icons.js`، جدول فقط `createTable`، متن و ارقام فارسی و RTL.

## تست

```bash
node --test tests/*.test.mjs                      # منطق: ارقام، تقویم شمسی (تطبیق با Intl)، انتقال کارها
NODE_PATH=$(npm root -g) node tests/smoke.cjs      # ۱۰ سناریوی رفتاری در مرورگر (سرور روشن باشد)
NODE_PATH=$(npm root -g) node tools/shots.cjs docs/screens   # عکس صفحه‌ها
```

## قدم‌های بعد

1. انبار: موجودی و خرید (جدول + هشدار کمبود)
2. مالی: پیمانکار، پرداختی، حقوق، بدهی
3. مدارک: قرارداد و عکس (نیاز به تصمیم درباره‌ی محل ذخیره‌ی فایل‌ها)
4. چند پروژه و نقش‌ها (مدیر، ناظر، مهمان) — نیاز به همگام‌سازی یا سرور
5. بسته‌بندی Capacitor و APK مثل حساب‌کتاب
