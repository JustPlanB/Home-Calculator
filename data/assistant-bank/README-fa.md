# بانک دادهٔ دستیار حساب‌کتاب (مرحلهٔ ۱)

هدف: داده‌ای ساختاریافته برای **سنجش و بهبود فهم زبان طبیعی دستیار آفلاین**، و در آینده (در صورت نیاز) آموزش یک مدل کوچک آفلاین. دستیار یک «منوی هوشمند» برای کار با دادهٔ خود برنامه است، نه چت‌بات عمومی.
اصل ثابت: **مدل/بانک فقط منظور را برچسب می‌زند؛ همهٔ محاسبات مالی را منطق قطعی برنامه روی دادهٔ واقعی انجام می‌دهد.** عدد انتظار در این بانک هم از یک دفتر ساختگی (`fixture.json`) با اسکریپت جدا حساب شده، نه از خروجی دستیار یا مدل.

## فایل‌ها
| فایل | محتوا |
|---|---|
| `train.jsonl` | ۶۶۵ نمونهٔ آموزش (قالبی + تنوع محاوره‌ای) |
| `dev.jsonl` | ۳۰۴ نمونهٔ ارزیابی (قالب‌های جملهٔ جدا، واژگان ردیف/دسته/ناشناخته و پیش‌گفتار جدا از train) |
| `hard.jsonl` | ۷۷ نمونهٔ دشوار دستی (فقط ارزیابی؛ ۷۴ فارسی، ۲ انگلیسی، ۱ ترکیبی) |
| `fixture.json` | دفتر ساختگی مرجع (۲۱ ردیف، دو ماه) + برچسب دستی دستهٔ هر ردیف |
| `capabilities.json` | تصویر ابزارها و آرگومان‌های واقعی دستیار در نسخهٔ ۱.۴.۴۲ |
| `SOURCES-fa.md` | منابع بررسی‌شده و وضعیت مجوز |
| `baseline-1.4.42-fa.md` | نتیجهٔ اجرای دستیار فعلی روی بانک و یافته‌ها |
| `baseline-1.4.42-dev-hard.json` | ریز نتیجهٔ dev و hard (برای مقایسهٔ بعدی) |

اسکریپت‌ها (`scripts/`): `assistant-bank-build.js` (ساخت، قطعی با seed ثابت)، `assistant-bank-check.js` (اعتبارسنجی؛ در CI با `tests/assert/assistant-bank.spec.js`)، `assistant-bank-run.js` (اجرای دستیار روی بانک و سنجش هم‌خوانی)، `assistant-bank-lib.js` (محاسبهٔ مرجع).

## طرح‌واره (هر خط JSON)
| فیلد | معنی |
|---|---|
| `id`, `split`, `lang`, `family` | شناسه، `train/dev/hard`، `fa/en/mixed`، خانوادهٔ قالب (پسوند `.aug` = نسخهٔ محاوره‌ایِ افزوده‌شده) |
| `context` | نوبت‌های قبلی کاربر (برای ادامهٔ مکالمه) |
| `text` | جملهٔ کاربر |
| `intent` | منظور: `sum count average max min list_rows group compare status balance savings trend forecast advice budget goal daily top anomaly recurring share chart navigate chat clarify refuse` |
| `action` | `run_tool` · `ask` (سؤال روشن‌کننده) · `refuse` (رد صادقانه) · `chat` · `navigate` |
| `tool`, `args` | ابزار و آرگومان‌های واقعی دستیار (فقط نام‌های موجود در `capabilities.json`؛ بدون سال/ماه) |
| `time` | `this_month` · `prev_month` · `all` · `unavailable` (دادهٔ آن بازه نیست) · `null` |
| `result_kind` | `sum/count/avg/rows` |
| `clarification` | `{reason, term}`؛ دلیل‌ها: `unknown_term vague_size missing_scope contradiction no_data_for_period market_price investment_advice write_operation out_of_domain …` |
| `reading` | `category` · `row` · `category_default` · `row_or_category` · `union` |
| `expected` | `{sum,count,incomplete[,row_alternative]}` از fixture؛ فقط برای جمع/تعداد/جست‌وجوی قابل‌محاسبه |
| `alt` | خوانش جایگزینِ پذیرفتنی (دسته به‌جای ردیف) با عدد خودش |
| `tool_alt` | ابزارهای هم‌ارز پذیرفتنی |
| `capability_gap` | `true` یعنی ابزار دقیق وجود ندارد؛ برچسب «نیاز واقعی» است نه «توان فعلی» |
| `difficulty`, `tags`, `notes`, `provenance`, `owner` | دشواری، برچسب‌ها، توضیح، `authored-template` / `authored-manual`، مالکیت |

## سیاست‌های برچسب‌گذاری (تصمیم‌ها)
1. **واژهٔ هم‌نام ردیف و دسته** («بنزین»، «نان»): پیش‌فرض **کل دسته** + پاسخ باید بگوید کل دسته است و عدد فقط ردیف‌ها را هم بدهد (`category_default` + `row_alternative`). با «ردیف/تراکنش …» = ردیف (`row`). برای واژه‌های ردیفیِ دیگر (`row_or_category`) هر دو خوانش پذیرفته است، به شرط اینکه دسته‌ای که عددش با ردیف فرق دارد عدد ردیف را هم بگوید.
2. **تطبیق واژهٔ کامل**، نه زیررشته: «نان» با «دانانو» نمی‌خواند؛ «قبض برق» عبارت یک ردیف است نه دستهٔ قبوض.
3. **و/یا** میان دو مورد = اجتماع (ردیف مشترک یک بار)؛ «بدون X و Y» = دو حذف.
4. **صفت اندازه** («کوچیک/بزرگ/ریز/درشت») با مرز مبلغ شرط نیست؛ بی مرز = سؤال `vague_size`. «بزرگ‌ترین/ده تا خرج بزرگم» = `max`.
5. **واژهٔ ناشناخته** (که در fixture نیست) در شرط/نفی/«فقط» = سؤال، بی عدد.
6. **زمان:** فقط ماه جاری/قبل/همه؛ دادهٔ نبوده («پارسال»، «دو ماه پیش») = پاسخ «ثبت نشده»، نه عدد و نه ماه دیگر.
7. **جمع بی‌نوع** (درآمد+هزینه) عدد واحد ندارد؛ فقط سه خط درآمد/هزینه/مانده. «چقدر شد؟» بی موضوع = سؤال.
8. پرداخت‌نشده در جمع می‌آید و جدا گفته می‌شود؛ ردیف بی‌مبلغ شمرده نمی‌شود و جدا گزارش می‌شود.

## جداسازی آموزش و ارزیابی
- هیچ جملهٔ مشترکی بین splitها نیست (اعتبارسنج بررسی می‌کند). هم‌پوشانی واژگان train/dev (Jaccard) ≈ ۰٫۳۰.
- dev از **واژگان ردیف/دسته/ناشناخته و قالب‌های زمان و پرسش** جدا از train ساخته شده (مثلاً train: اسنپ/برنج/قبض برق/دکتر؛ dev: تپسی/سینما/قسط وام/قبض آب/دانانو/دارو). ساختار منظور (intentها) بین دو split مشترک است، چون هدف سنجش تعمیم زبانی است.
- `hard` دستی است و هرگز نباید در آموزش بیاید.
- افزایش داده: ۴۰۰ نمونهٔ train با پیش‌گفتار محاوره‌ای («آقا»، «ببخشید») و املای عامیانهٔ امن؛ برچسب عوض نمی‌شود.

## آمار
- **۱۰۴۶ نمونه:** train ۶۶۵ · dev ۳۰۴ · hard ۷۷. اقدام‌ها (کل): `run_tool` ۸۵۸، `ask` ۱۲۶، `refuse` ۲۹، `chat` ۱۸، `navigate` ۱۵ (تقریبی بر اساس splitها: train ۵۲۶/۹۲/۲۱/۱۴/۱۲، dev ۲۷۰/۲۲/۵/۴/۳، hard ۶۲/۱۲/۳/۰/۰).
- ۶۷۵ نمونه عدد انتظار از fixture دارند؛ ۵۰ نمونه با ادامهٔ مکالمه (`context`)؛ ۱۱ نمونه `capability_gap`.
- بیش از ۶۰ برچسب موضوعی: `negation`، `union`، `whole-word`، `size-adjective`، `follow-up`، `category-vs-row`، `unknown`، `vague`، `time`، `amount` و غیره.

## محدودیت‌ها (صریح)
- **همهٔ جمله‌ها و برچسب‌ها را یک دستیار هوش مصنوعی نوشته**، نه کاربر واقعی؛ نمایندهٔ توزیع واقعی گفتار کاربران نیست. نمونهٔ واقعی (با رضایت و بی‌اطلاعات شخصی) باید بعداً جدا افزوده شود.
- fixture فقط دو ماه و ۱۱ ردیف دارد؛ سال، پروژه، چندحساب، جیب‌به‌جیب، روز ماه و هفته در آن نیست.
- تحلیل‌ها (`status/balance/savings…`) عدد انتظار ندارند؛ فقط برچسب ابزار.
- نمونه‌های انگلیسی/ترکیبی فقط سه تاست؛ دستیار فعلاً فارسی است.
- مقصدهای «برو به …» فقط از پیام راهنمای دستیار گرفته شد؛ فهرست رسمی جدا وجود ندارد.
- برچسب‌های `tool_alt/alt` محافظه‌کارانه‌اند؛ اختلاف‌های مرزی باید با بازبینی انسانی بسته شوند.
- مجوز: محتوای بانک اصیل و متعلق به پروژه است؛ **پروژه هنوز مجوز صریح برای داده‌های خود تعیین نکرده** (در گزارش آمده).
