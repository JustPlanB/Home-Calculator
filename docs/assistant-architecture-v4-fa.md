## ۱. مأموریت، اولویت و خطوط قرمز

**مأموریت:** دستیار مالی کاملاً آفلاین، با مکالمهٔ طبیعی و روان فارسی؛ کاربر مثل گفت‌وگو با یک انسان سؤال می‌پرسد، به شکل‌های مختلف می‌گوید، ادامه می‌دهد، اصلاح می‌کند و پاسخ قابل‌فهم می‌گیرد.

**ترتیب اولویت:** ۱) فهم زبان طبیعی ← ۲) فهم منظور ← ۳) پاسخ طبیعی و کوتاه ← ۴) پیوستگی مکالمه ← ۵) صحت مالی ← ۶) قابلیت‌های پیشرفته.

**خطوط قرمز (وتو):**
۱. هیچ عدد مالی حدس‌زده یا ساخته‌شده نمایش داده نمی‌شود.
۲. هیچ فرض اثرگذار بر نتیجه پنهان نمی‌ماند.

**قیدهای ساختاری:** کاملاً آفلاین؛ بدون API/اینترنت/مدل زبانی آنلاین؛ **مدل زبانی محلی وارد معماری نمی‌شود**؛ بازنویسی از صفر ممنوع مگر با دلیل فنی مستند؛ دستیار فقط‌خواندنی است.

**اصل طراحی:** ورودی منعطف، خروجی سخت‌گیر. Interpret سخاوتمند و فازی؛ Execute تنها مرجع عدد.

## ۳. معماری پنج‌بخشی

```
UI چت ⇄ Orchestrator ──متن+حالت(فقط‌خواندنی)──► Interpret ──IR──┐
            ▲   │                                                  ▼
            │   └──── commit(نتیجه) ◄──────────────────────── Execute (تنها درگاه توابع مالی)
            │                                                      │ Result(ThinQuantity→Quantity)
            └────────────────────── Respond ◄──────────────────────┘
Trace: همه فقط می‌نویسند (بدون متن/مبلغ/هویت)
```

| بخش | مسئولیت | ورودی → خروجی | دسترسی | **ممنوع** |
|---|---|---|---|---|
| **Orchestrator** | چرخهٔ نوبت، snapshot نوبتی، `todayKey`، `DialogueState`، فراخوانی اجزا، Trace | متن کاربر → نمایش | مالک حالت مکالمه | تفسیر زبان، محاسبهٔ مالی |
| **Interpret** | نرمال‌سازی، واژگان، غلط تایپی، اعداد/تاریخ فارسی، نفی/استثنا، ellipsis/ضمیر، تولید IR و نامزدهای برداشت | متن + `DialogueState`(خواندنی) + EntityIndex(نام‌ها) → IR | فقط واژگان/شاخص نام‌ها | **هر محاسبهٔ مالی؛ هر دسترسی به ردیف‌ها/توابع** |
| **Execute** | اعتبارسنجی IR، اجرا از طریق فهرست سفید توابع امن، تولید Quantity | IR → Result | **تنها** ماژول با دسترسی به توابع مالی اپ؛ فقط‌خواندنی | تعبیر معنای جمله؛ نوشتن؛ توابع ناامن؛ ساخت متن |
| **Respond** | تبدیل Result معتبر به پاسخ طبیعی؛ echo؛ سیاست Q1/Q2/Q4/Q5 | IR + Result → View | فقط Result | **ساخت/محاسبهٔ هر عدد**؛ دسترسی به ردیف |
| **Trace** | ثبت رویدادهای فنی مجاز | رویداد → بافر | فقط‌نوشتنی | ذخیرهٔ متن خام، مبلغ، شرح، نام، حساب، تاریخ دقیق؛ تأثیر بر رفتار |

### ۳.۱ IR استاندارد v1 (حفظ‌شده از v3.5)
فیلدها: `intent, measure, period, flow, filters{include,exclude}, group, view, statusScope, topicRef, slotOrigin, alternatives, confidence, ambiguityFlags`.
- `slotOrigin[slot] ∈ {explicit, inferred, inherited, defaulted, unspecified}`.
- مقادیر پیش‌فرض (Q1): `view=card`، `statusScope=total`، با `slotOrigin=defaulted` و **اعلام اجباری در جملهٔ اول**.
- `alternatives`: حداکثر یک برداشت دوم با برچسب `cheap: bool`.
- IR کانونی است؛ **تنها آداپتور زمان اجرا**: `irToLegacy` تا N6؛ `legacyToIR` فقط برای مقایسهٔ سایه در آزمون.

### ۳.۲ قواعد پاسخ (قابل‌آزمون)
**R1 (Q1):** برای «خرج/درآمد من» ← عدد کارت (paid+unpaid). خط «پرداخت‌نشده: X» فقط اگر X>0. اگر Σ همهٔ ردیف‌ها ≠ عدد کارت: خط علت (فهرست علت‌های ممکن از F12: ردیف پروژه‌ای، بخش غیر شخصی، وضعیت نامشخص…؛ هیچ علتی که اثباتش نشده گفته نمی‌شود).
**R2 (Q2):** جملهٔ اول = بازگویی برداشت + همهٔ فرض‌های اثرگذار (بازهٔ زمانی، `view`، `statusScope`، فیلتر مستنتج). برداشت دوم فقط اگر: فقط‌خواندنی ∧ همان snapshot ∧ یک محاسبهٔ اضافه ∧ بدون تابع ناامن ∧ زیر بودجهٔ زمانی (F13). نمایش جدا؛ بدون Δ یا ترکیب. پرسش فقط اگر اطمینان زیر کف یا برداشت‌های متناقض بدون اولویت یا ورودی بی‌معنی.
**R3 (Q3):** `Count/List/Avg(ردیفی)/Group` فقط روی ردیف‌های دارای مبلغ؛ خط «N ردیف ناقص» اگر N>0 (ردیف با اطلاعات ولی بدون مبلغ). ردیف کاملاً خالی گزارش نمی‌شود. `Sum` رفتار فعلی (ردیف صفر اثر ندارد).
**R4 (Q4):** ساختار: جملهٔ اصلی کوتاه؛ سپس خط‌های جدا فقط وقتی مرتبط (پرداخت‌نشده، علت تفاوت، برداشت دوم، هشدار ناسازگاری). هیچ خط خالی. برداشت دوم با عنوان مستقل.
**R5 (Q5):** ردیف ناسازگار = تخصیص بیش از مبلغ ردیف، تخصیص منفی، یا `mixed` با تخصیص صفر. عدد داشبورد بی‌تغییر + «N ردیف ناسازگار: علت». عدد جایگزین (بدون این ردیف‌ها) فقط‌خواندنی، همان snapshot، جدا و با برچسب؛ هرگز جایگزین یا ترکیب نمی‌شود؛ اگر ایمن/قابل‌اتکا نیست (F1/F12 ناتمام یا شرط‌های R2 برقرار نیست) فقط هشدار.
**R6:** هر عدد نمایشی = token متصل به Quantity (N5: ThinQuantity؛ N7: Quantity کامل). عدد بدون token ⇒ Block.
**R7:** سه رده: **Block** (هرگز: عدد ساخته‌شده، Stock×Flow، ÷۰، Share با part⊄whole، عدد کهنه به‌جای تازه)؛ **Caveat** (پاسخ + هشدار: ماه ناقص با کامل، ردیف ناسازگار، ردیف بی‌وضعیت)؛ **Free**.

### ۳.۳ قراردادهای داده
- **ThinQuantity (N5):** `{value, unit, period, policyAsCalled, source:'legacyTool:<name>', thin:true}`.
- **Quantity (N7):** `kind, value, unit, dataState, validity, confidence, role, period, policy, rounding, flags, provenance{family, expr, source, formula, derivedFrom, dataVersion…}` (تعریف تفصیلی v3.3 بخش ۷؛ بدون تغییر).
- **DialogueState (N4):** `turn, active, topics[≤۳], pending?, version`؛ هر Topic: `label, constraint, lastIR, lastResult, mentions[{shown}]`؛ فقط Orchestrator می‌نویسد.
- **RowRef:** `SnapshotAddr + stableId? + idState + fp`؛ fp هرگز تطبیق خودکار نمی‌کند (v3.3).
- **تعریف‌ها:** `isBlank/isDraft/isMaterial` و `statusClass` (paid/unpaid/empty/other) مطابق v3.3؛ مبلغ واحد: تومان.
- **DataVersion (N7):** هش محتوایی؛ تا آن زمان هر نوبت همهٔ اعداد را دوباره محاسبه می‌کند.
- **Trace:** فقط فیلدهای فهرست سفید: نسخهٔ طرح، شناسهٔ الگوی IR، `intent`، نوع Measure، `slotOrigin`، `ambiguityFlags`، باکت شمارش/زمان، `dataState/validity/confidence`، کد خطا، رخداد «پرسش/اصلاح/رها». رشتهٔ آزاد پذیرفته نمی‌شود؛ آزمون خودکار؛ لاگ قدیمی دست‌نخورده تا P1-T4.
