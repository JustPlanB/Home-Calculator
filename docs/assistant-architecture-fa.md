# معماری فهم در دستیار (۱.۴.۴۰)

همه‌چیز آفلاین و روی گوشی است؛ هیچ مدل، API یا درخواست شبکه‌ای در مسیر فهم نیست و دستیار فقط‌خواندنی می‌ماند.

## جریان
```
متن کاربر
  → hkAsstAliasIntent   «X یعنی Y» را (فقط روی گوشی) به‌عنوان اصطلاح شخصی ذخیره می‌کند
  → hkAsstAliasApply    اصطلاح‌های شخصی را در متن جایگزین می‌کند (فقط تطبیق کامل کلمه)
  → hkAsstSemantic      (18d) فهم: نرمال‌سازی، عبارت‌های چندکلمه‌ای، قصد، نوع، زمان، موضوع، کلمه‌های ناشناخته
                        یا برای قصدهای ویژه (گفتگو، تحلیل، رفتن به بخش، نمودار…) مستقیم فرمان می‌دهد
  → hkAsstDecide        (18j) اجرا / پرسش روشن‌کننده («آبان چطور؟» بدون گفتگوی قبلی)
  → hkAsstFrameToCommand (18j) ساخت فرمان ابزار + پیشنهاد جایگزین
  → hkAsstCtxMerge      (18i) حافظهٔ گفتگو؛ فقط آنچه HK_ASST_INTENT_SPEC[قصد].carry اجازه می‌دهد منتقل می‌شود
  → hkAsstExec          ابزارهای فقط‌خواندنی (18c، 18h، 18i)
```

## قاعدهٔ کلمه‌ها
- کلمهٔ ساختاری (چند، جمع، بیشترین، مقایسه، ماه، درآمد…) ← مفهوم.
- کلمهٔ محتوایی ناشناخته (اسنپ، مرغداری، باغ…) ← حذف نمی‌شود؛ `args.text` می‌شود و جمله را خراب نمی‌کند.
- غلط‌یاب تقریبی فقط برای واژه‌های ساختاری و واژه‌های موجود در داده است؛ نام‌ها و موضوع‌ها دست نمی‌خورند.
