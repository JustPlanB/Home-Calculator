# سند تحویل پروژهٔ «حساب‌کتاب» (برای ادامهٔ کار با هر دستیار هوش مصنوعی یا برنامه‌نویس)

این سند همه‌چیزهایی را جمع می‌کند که برای ادامهٔ کار از همین نقطه لازم است: قاعده‌های صاحب پروژه، ساختار کد، روند ساخت و انتشار، و کارهای باز.
قاعده‌های فنی دائمی در `CLAUDE.md` (ریشهٔ مخزن) هم هست؛ این سند آن را کامل می‌کند و جایگزینش نیست. هر دو را اول کار بخوانید.

آخرین به‌روزرسانی این سند: نسخهٔ **۱.۳.۹۷** (versionCode ۶۲۴).

---

## ۱. متن آماده برای شروع کار با یک دستیار تازه
این متن را اول گفتگو به دستیار بدهید:

> روی مخزن `JustPlanB/Home-Calculator` (نرم‌افزار اندرویدی حساب‌کتاب خانگی با Capacitor) کار می‌کنی. اول `CLAUDE.md` و `docs/HANDOFF-fa.md` را کامل بخوان و همهٔ قاعده‌هایش را رعایت کن. فقط فارسی جواب بده. هر جا گفتم «توضیح فقط»، چیزی در کد تغییر نده (عکس و طرح ساختن مجاز است)؛ فقط وقتی گفتم «بساز» تغییر بده. کارهای باز در بخش ۹ همین سند است.

---

## ۲. قاعده‌های گفتگو (صاحب پروژه این‌ها را خواسته)
- **فقط فارسی** جواب داده شود.
- همیشه **«نرم‌افزار»** گفته شود، هرگز «اپ» (در متن‌های داخل نرم‌افزار و یادداشت‌های نسخه هم).
- **«توضیح فقط»** (یا هر سؤال توضیحی): فقط توضیح، هیچ تغییری در نرم‌افزار نه. ساختن عکس یا طرح برای نشان دادن ایده مجاز است.
- **«بساز»** یعنی اجازهٔ تغییر و انتشار.
- برای هر کاری که به انتشار می‌رسد، یک **جدول زمان‌بندی به وقت ایران** (UTC+3:30) داده شود.
- فقط **دادهٔ ساختگی** در تست‌ها و عکس‌ها؛ هرگز دادهٔ واقعی کاربر باز نشود.
- بدون اجازهٔ صریح به این‌ها دست زده نشود: workflowهای `.github/workflows`، Secretها، کلید امضای APK، شاخهٔ `update-feed`. انتشار با ادغام در `main` از قبل مجاز است.
- شاخهٔ `backup/unsplit-v1.3.59` («ورژن جدا نشده») هرگز تغییر نمی‌کند و پاک نمی‌شود.
- ایمیل و اطلاعات شخصی صاحب پروژه به هیچ سرویس بیرونی داده نشود.

## ۳. قاعده‌های طراحی (خلاصه؛ متن کامل در `CLAUDE.md`)
- **بی‌پرش:** هیچ چیز جلوی چشم کاربر یک‌دفعه نپرد. پنجره‌ای که صفحه‌کلید می‌خواهد از اول با اندازهٔ «صفحه‌کلید باز» چیده شود (`hkKbFreeBottom`). عوض کردن تب، صفحه‌کلید را نبندد. جابه‌جایی تب‌ها با افکت نرم باشد.
- در رابط دسته‌ها همیشه «واریزی» (سمت راست) و «برداشت»، به همین ترتیب.
- **آیکون‌ها یکسان:** مداد ویرایش `HK_EDIT_SVG`، حذف × قرمز `HK_DEL_X`، پوشه `HK_FOLDER_SVG`، تیک `HK_TICK_SVG`. حرف ✓/✔ هیچ‌جا به کار نرود، حتی در کد بومی.
- **فونت وزیر** همه‌جا، در کد بومی هم: `ResourcesCompat.getFont(…, R.font.hk_vazir_*)`.
- **رنگ‌های ثابت:** درآمد `#9ee858`، مخارج `#ff6b4a`، شخصی `#ff9f0a`، آبی `#08b5f5`، پرداخت‌نشده `#ffec0a`. رنگ هر دسته در `HK_CAT_COLORS` ثابت است. دسته‌های ساخت کاربر از ۸ رنگ `HK_USER_CAT_COLORS` رنگ می‌گیرند (تکرار مجاز، قرمز نه) و آیکونشان از ۱۵۰ آیکون `HK_ICON_PICK` است.
- تیرگی پشت پنجره‌های شناور مثل منوی «+» است (`.hk-add-ov`: `rgba(0,0,0,0.16)` با `blur(1.5px)`).

## ۴. ساختار کد
- منبع ویرایش **`src/`** است: `src/html/*`، `src/css/*`، `src/js/*` به ترتیب `src/parts.txt`. فهرست مطالب: `src/README-fa.md`.
- همهٔ بخش‌های JS در یک اسکریپت و یک دامنهٔ مشترک کنار هم گذاشته می‌شوند (ترتیب مهم است).
- **`index.html` مستقیم ویرایش نمی‌شود.** بعد از هر ویرایش در `src/` این دو اجرا شوند و هر دو (src و index.html) کامیت شوند:
  ```
  node scripts/assemble-index.js
  node scripts/src-toc.js
  ```
- کد بومی اندروید: `android-src/*.java` (بستهٔ `ir.hesabketab.app`). `scripts/patch-android.js` آن‌ها را در پروژهٔ اندروید کپی می‌کند و manifest، layoutها و drawableها را می‌سازد. پوشهٔ `android/` در مخزن نیست و نباید کامیت شود.
- هر تغییر در شکل دادهٔ ذخیره‌شده یک تبدیل شماره‌دار در `HK_MIGRATIONS` می‌گیرد.
- **بخش‌های مهم:**

  | بخش | کجا |
  |---|---|
  | دسته‌بندی هوشمند شرح‌ها (`HKCategorizer`) و بانک کلمه‌ها (`EXTRA_KW`، `EXTRA_KW2`) | `src/js/06b-cat-stamp-row.js` |
  | باکس هوشمند (اسلایدها و لانگ‌پرس روشن/خاموش) | `src/js/06c-todo-ym.js` |
  | شخصی‌سازی (`openPrefsModal`، `HK_SP_LABELS`) | `src/js/15b-prefs.js` |
  | ثبت پیامک (`confirmSmsEntry`) | `src/js/09c-…` |
  | باکس ثبت و دسته‌ها و جیب به جیب | `src/js/10a2-hk-cat-user-map.js` |
  | خواندن صف پیامک‌های بومی (`pollPendingSms`) | `src/js/10c-get-app-lock-plugin.js` |
  | بازگشت گوشی (`onBackGuard`) و بازگشت یک مرحله‌ای منوی همبرگری | `src/js/14-theme.js` |
  | اعلان پیامک، ثبت سریع و دکمه‌های دسته | `android-src/BankSmsReceiver.java` و `HkQuickReplyReceiver.java` |

## ۵. تست‌ها
- تست‌ها در `tests/assert/*.spec.js` (Playwright، فقط دادهٔ ساختگی) هستند. هر نسخه یک فایل `batch-13xx.spec.js` دارد.
- **اجرای یک تست:** `node tests/assert/batch-1397.spec.js`
- **اجرای کامل:** `node tests/run.js` (با `HK_SHARD=i/4` برای تکه‌تکه).
- در CI همهٔ تست‌ها دو بار اجرا می‌شوند: یک بار روی منبع، یک بار روی فایل ساخته‌شده (`HK_INDEX`). هر کدام ۴ تکهٔ هم‌زمان دارد. علاوه بر این‌ها `build-check` (کامپایل جاوا)، `publish-dryrun` و `ios-simulator` هم اجرا می‌شوند.
- پیش از PR فقط تست‌های مرتبط محلی اجرا شوند. ادغام فقط با CI سبز.
- تست‌هایی که متن کد بومی را بررسی می‌کنند از `tests/lib/android-src.js` می‌خوانند.
- پیش از انتشار تغییرات ویجت، اعلان، پیامک یا یادآور: `docs/android-device-checklist-fa.md`.

## ۶. روند انتشار (هر نسخه)
1. `version.json`: `versionCode` یکی بالا برود، `versionName` تازه شود، و `notes` حداکثر ۴ خط باشد (بی «اپ»). در `package.json` هم `version` همان شود.
2. تست‌های مرتبط اجرا شوند. وقتی تستی در حال اجراست، `tests/out` پاک نشود.
3. مطمئن شوید پوشهٔ `android/` در کامیت نیست.
4. کامیت، push روی شاخهٔ کار، و ساختن PR به `main`.
5. حدود ۱۳ دقیقه صبر برای CI، بعد بررسی همهٔ چک‌ها.
6. ادغام با روش «merge» (نه squash).
7. شاخهٔ کار دوباره روی `main` گذاشته شود:
   ```
   git fetch origin main && git checkout -B <شاخه> origin/main && git push --force-with-lease
   ```
8. حدود ۹ دقیقه بعد، workflow «Build Hesab Ketab APK» یک Release تازه (`v<نسخه>-b<بیلد>`) با `hesab-ketab.apk` می‌سازد و `version.json` شاخهٔ `update-feed` را به‌روز می‌کند. به‌روزرسانی داخل نرم‌افزار از همین می‌خواند.
9. گزارش به صاحب پروژه به فارسی، با لینک فایل نصب و جدول زمان‌بندی.

جزئیات بیشتر: `docs/release-fa.md`.

## ۷. نکته‌های فنی که در گفتگوها روشن شد
- **محدودیت نوتیف اندروید:** متنی که در جای پاسخ نوتیف (ثبت سریع) تایپ شده، فقط با فلش ارسال به نرم‌افزار می‌رسد. اگر بدون فلش دکمهٔ دیگری زده شود، اندروید آن متن را دور می‌اندازد و هیچ راهی برای خواندنش نیست.
  - **راه‌حل فعلی (۱.۳.۹۶ و ۱.۳.۹۷)، هر دو ترتیب:**
    - **اول شرح، بعد دسته:** شرح با فلش فرستاده می‌شود، بعد اعلان «بابت: …» با دکمه‌های دسته می‌آید.
    - **اول دسته، بعد شرح:** دسته زده می‌شود، بعد اعلان «… ثبت شد» با «افزودن شرح» می‌آید. نرم‌افزار تا ۳۰ ثانیه صبر می‌کند (`quickWait`).
- **پیشنهاد بعدی، هنوز ساخته نشده:** باکس شناور خودمان (`HkQuickActivity`) با شرح‌های آماده، حدس زندهٔ دسته و ثبت خودکار حدس‌های مطمئن. جزئیات در بخش ۹.
- **جیب به جیب:** ردیف‌هایی که فقط بین کارت‌های خود کاربر جابه‌جا می‌شوند. در جمع درآمد و مخارج نیستند ولی در موجودی هستند. از ۱.۳.۹۷ علامت همان لحظهٔ ساختن ردیف گذاشته می‌شود (`hkSmsStamp`)، و ردیف تازه زمان ساخت می‌گیرد تا جفت‌یابی خودکار (`hkP2PFindPairs`) کار کند.
- **عمومی بودن مخزن:** مخزن عمومی است و کد و فایل‌های نصب برای همه دیده می‌شود. رمزها در Secrets هستند. اگر مخزن خصوصی شود، **به‌روزرسانی داخل نرم‌افزار از کار می‌افتد**، چون از `raw.githubusercontent.com/.../update-feed/version.json` و Releases عمومی می‌خواند. اول باید جای دیگری برای این فایل‌ها ساخت.
- آمار بازدید مخزن فقط برای صاحب آن در GitHub ← Insights ← Traffic دیده می‌شود (۱۴ روز آخر). شمار دانلود فایل نصب در اطلاعات هر Release هست.

## ۸. وضعیت فعلی (۱.۳.۹۷)
- **ساخته و منتشر شده:**
  - روشن/خاموش اسلایدها با لانگ‌پرس، در باکسی وسط صفحه: ۵ ردیف، عرض به اندازهٔ نوشته‌ها و تیرگی پشت مثل منوی «+».
  - «کارهای من» روشن/خاموش ندارد. لانگ‌پرس روی اسلاید «+» کاری نمی‌کند.
  - بازگشت در منوی همبرگری یک مرحله عقب می‌رود.
  - کشیدن افقی بین تب‌ها در باکس‌های تب‌دار: دسته‌ها، اولویت دسته‌ها، آمار، شروع.
  - رفع جیب به جیب.
  - ثبت سریع با هر دو ترتیب.
  - بانک کلمهٔ دسته‌ها حدود ۲۱۰۰ کلمه.
- **باید روی گوشی واقعی امتحان شود:** اعلان «افزودن شرح» بعد از زدن دسته.

## ۹. کارهای باز و پیشنهادهای منتظر تأیید
- **باکس شناور ثبت سریع (پیشنهاد بهترین راه):**
  - نوتیف ساده که با لمسش باکس خودمان باز می‌شود.
  - در باکس: شرح‌های آماده از سابقه (یک لمس = شرح و دسته با هم)، جای شرح با صفحه‌کلید از قبل باز، و دکمه‌های دستهٔ اختیاری.
  - تراکنش‌های بی‌جواب به «تکمیل اطلاعات» می‌روند.
  - **نسخهٔ بعدی:** حدس دسته از متن پیامک و سابقه، و ثبت خودکار حدس‌های مطمئن. باز شدن خودکار باکس با مجوز «نمایش روی برنامه‌های دیگر» فقط به‌صورت گزینهٔ اختیاری.
- **پیشنهاد شده ولی تأیید نشده؛ بدون درخواست انجام نشود:**
  - کش و تلاش دوباره در Gradle داخل workflowها.
  - ساخت جداگانه برای بازار (بدون به‌روزرسانی خودکار).
  - بازبینی کامل امنیتی و باگ‌ها.

## ۱۰. پشتیبان کامل مخزن
- خود GitHub نسخهٔ اصلی است: `https://github.com/JustPlanB/Home-Calculator`
- **گرفتن نسخهٔ کامل با همهٔ شاخه‌ها و تاریخچه:**
  ```
  git clone --mirror https://github.com/JustPlanB/Home-Calculator.git
  ```
- **اگر فایل bundle دارید** (مثلاً `hesab-ketab-repo.bundle`)، بازگردانی آن:
  ```
  git clone hesab-ketab-repo.bundle Home-Calculator
  cd Home-Calculator
  git remote set-url origin <آدرس مخزن تازه>
  git push --all origin
  git push --tags origin
  ```
- برای ساختن APK در مخزن تازه، Secretهای کلید امضا باید دوباره در تنظیمات GitHub گذاشته شوند. **همان کلید قبلی لازم است**، وگرنه نسخه‌های نصب‌شده به‌روز نمی‌شوند. کلید را جای امنی بیرون از مخزن نگه دارید.
